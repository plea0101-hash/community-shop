# 公開展示型試營運：驗收與Go／No-Go檢查清單

僅驗收規劃，**全部待實作後提供證據，未執行或通過**。基準／範圍見[MVP計畫](public-demo-mvp-plan.md)及[虛擬角色設計](public-demo-virtual-experience.md)。本次允許新製作的四角色／三後台本機模擬，替代舊純內容限制，仍禁止原取消／正式登入／管理端點。本輪不測正式API、不執行SQL、不部署、不操作任何資料／權限；不將舊取消模組測試當展示驗收。

現行受審範圍為8–12專注人日規劃的最小互動版，含四角色／三後台本機模擬；不以完整商用66–100估算的真Auth／權限／交易系統驗收替代，也不據模擬結果宣稱商用已完成。

## 2. 驗收規劃

| C08 程式／資料邊界 | 真精確戶數／詳址／聯絡／文件／帳號／預約、Auth token／service_role／機密不得在HTML/JS/JSON/source map或快取／log出現 | 待產物＋公開URL與秘密掃描審閱（紀錄遮蔽值）；公開publishable key不是secret，但展示也不帶入正式project設定 |

無後端的最小可互動版不需要DB。未來若另核准DB展示方案，上述C06／C07須重訂：獨立無正式資料的Supabase需先審ACL/RLS、僅合成公開投影、無寫入／Auth／正式RPC，403／超時／500友善錯誤且不fallback到假會員；不得以純靜態的「不適用」條件通過真API方案，另估工作與核准。

## 3. Go標準（缺一不可）

- 已有指定commit／hash的隔離展示產物，C01–C17有相符證據；不適用項須具體說明選定方案，不可一律勾掉安全驗收。
- 無真個資／精確戶數／機密、正式會員／預約／付款／管理／測試入口或正式Supabase依賴／env繼承；允許新的四角色模擬入口與本機操作，虛構標示完整、不宣稱Auth或安全授權。
- 手機／桌面／錯誤與路徑隔離驗收完成；未測瀏覽器／裝置或主機限制明列，核心安全不能用「日後補測」放行。
- 本人明確核准展示隔離、舊環境／公開API風險處置與殘餘風險責任、發布與回退；原A/B未執行不被當已修。若舊暴露無法處理且無獨立正式決策，不能Go。
- 後續部署只針對另行核准的展示專案／網址／產物／時段，不合併PR、不觸發正式權限／migration。核准前所有動作停在備件。

## 4. No-Go條件

任一必要證據缺失、正式key／API被帶入、精確戶數或敏感資料仍可由展示內容／服務取得、原測試／正式登入入口可用、模擬角色被誤稱正式Auth或未標示非真實金流、假合作／可預訂文案、隔離設定不明、舊正式風險未記錄／未核准處置、無回退或無本人部署核准，均不得公開發布。純靜態站不能用「DB目前403」「按鈕disabled」「robots禁止」或「沒有真會員」替代隔離與模擬界線驗收。

**目前No-Go**：只有計畫，無新的展示產物、實測與正式發佈／風險核准。本輪任何文件檢查完成都不改此狀態。

## 5. 異常處理與回退（後續另行核准）

隔離產物若驗收失敗，停在未公開預覽／本機，不動原站。公開後若發現洩漏／正式業務入口或原型／錯誤連線，按事先核准方案停用該展示或退到已驗收的純內容維護頁，記錄發現時間、受影響hash與最小證據；處理主機／快取、連結與公開副本需另核准，不刪原正式資料或稽核。已下載個資不能保證追回。

只可回到已驗收的隔離展示版本，**不可把原main的正式config／精確戶數頁當安全回退**。若新展示是首版，回退可採維護頁或撤下該獨立展示，不切正式網域、不自動更改ACL／RLS／旋轉金鑰／補service_role DML。秘密若另被發現，先記錄並提出相應處理，不將publishable key與service_role混為一談。

對外發布後的HTTP／資產／無正式請求等只讀抽查須另核准環境與時段；不在正式庫造測試資料或做TRUNCATE／預約／付款測試。本輪不執行任何回退／發佈或驗收測試。
