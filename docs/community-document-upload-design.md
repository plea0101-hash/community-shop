# 社區申請：文件上傳說明與範例設計

狀態：需求、畫面與測試規劃，未實作。只更新文件與Draft PR #2，不改程式、SQL、Supabase或正式權限，不部署、不合併、不核准A／B。復用community_registrations，不以本文件另建正式申請來源。

## 1. 已確認送審條件

- 社區正式送審必須具備兩項證明：**管理組織身分證明**及**申請人管理授權證明**。
- 允許先儲存草稿；缺任一項文件不得正式送審，但可保存與繼續補齊。其他申請欄位的必填時點仍待確認。
- 文件齊備只代表可送審，不能自動代表資格通過；未通過平台資格審核，不取得社區管理、場地／檔期管理或進駐審核權。
- 同一份文件可同時引用於兩項證明，不要求重傳或複製檔案；兩項資格各自審核、決定及留理由／紀錄。任一項待補或不通過，不能因另一項通過自動開權。
- 範例不是唯一接受文件清單；其他等效文件可供平台審核。具體真實性、效期、簽章、內容充分性與例外認定尚待確認。

## 2. 每個上傳欄位的說明設計

以下為產品文案草案；文件名稱是可能的證明類型，不宣稱特定機關必會核發或一定足以通過，也不要求全部上傳。

| 欄位旁資訊 | 管理組織身分證明 | 申請人管理授權證明 |
|---|---|---|
| 用途／審核目的 | 確認申請社區的管理組織及其與社區的關係；不以社區同名即認定同一組織 | 確認申請人確有權代表該社區／管理組織辦理平台申請與管理；不以持有組織文件即認定個人有權 |
| 可供審核的文件類型／具體例子 | 例如管理委員會報備或核備相關文件、組織成立／選任決議的相關節錄，或其他能證明管理組織身分的等效文件 | 例如管理組織出具的授權書、明確記載代表人／授權事項的會議決議節錄、含適當授權內容的委託管理文件，或其他等效證明 |
| 可向誰取得 | 可先洽社區管委會、管理中心或現有管理組織；涉及報備文件，可依當地受理流程洽相關主管機關確認申請方式，不保證平台代為取得 | 可洽有權授權的管理組織／負責人或受託管理單位；是否有權出具與代表範圍由審核確認，不能只請任意住戶簽名 |
| 查看文件範例 | 「查看文件範例」開啟虛構資料示意與用途說明，另有「其他等效文件也可提出」提示 | 「查看文件範例」開啟虛構授權示意，說明須能看出授權者、申請人、社區及授權範圍，非強制法律格式 |
| 常見問題 | 「沒有這個名稱的文件怎麼辦？」→提供其他等效文件／詢問客服；「成立中或特殊管理型態？」→先存草稿詢問，不自行認定資格 | 「不是主委可以申請嗎？」→需證明本人受適當授權，具體標準待確認；「同份文件證明兩項？」→可引用但分別審核 |
| 特殊情況 | 提供「詢問客服」入口，說明組織型態或取得困難；可選擇關聯自己的申請編號，不將文件公開留言 | 提供「詢問客服」入口，說明交接、無法聯繫原管理人或授權疑問；客服回覆不等於核准或交接自動豁免 |

客服候選為登入後私人詢問表單／工單，或平台正式指定的私密客服通道；實際管道、收件者、回覆時效尚未確認，不虛構email、電話或既有可用客服。管道未設定時不顯示假連結，正式開放前須補齊；不引導把證件傳到公開留言或本PR。

### 「查看文件範例」內容草圖

**管理組織示意（虛構，僅供辨識資訊位置，非官方文件）**：

> 示意社區甲管理組織／組織名稱位置／與示意社區甲的關係位置／出具或決議日期位置／相關佐證資訊位置。請僅提供審核必要頁面，其餘個資可依審核指引遮蔽。

**管理授權示意（虛構，非制式授權書或保證可通過）**：

> 示意社區甲管理組織授權「申請人甲」辦理平台社區申請及適用管理事項；示意出具日期／授權範圍／授權人或組織資訊位置。實際授權者資格、效期與簽章要求待確認。

範例頁以「示意／虛構」醒目標記，無真實姓名、證號、電話、地址、簽名或印章；不展示其他申請人原件或公開Storage URL。可用文字及去識別示意圖，實際圖檔／下載範本本輪未製作；不得把範例輸入欄位直接變成新增必填項。

## 3. 畫面與資料流程

1. 登入後進入自己的社區申請，區分基本資料及「資格文件」區。兩個證明卡片各包含上表的用途、類型／例子、取得對象、範例、FAQ及客服入口，鍵盤與手機可操作，不只以滑鼠懸浮顯示。
2. 每卡提供「上傳文件」及「引用本申請已上傳文件」。顯示檔案狀態與自己的安全檔名、分別的資格審核狀態；不以文件數量判斷兩項都已證明。
3. 隨時「儲存草稿」。例如只上傳組織證明：保存成功、授權證明待補、不能送審；兩卡同引一份完成檢查的文件：可提出兩項供分別審核，不因共用而拒絕。
4. 「正式送審」缺項時逐項提示，可導回補件；前端提示之外，受控送審交易須重驗兩項關聯文件屬於本人申請、上傳完成且可供審核，不信任client的「齊備」欄位。未完成／損壞／安全檢查未過的檔案不能假裝具備證明。
5. 正式送審綁定文件版本與兩項引用快照。平台審核者分別檢查資格、要求補件／通過／不通過並留紀錄；最後資格核准與可信社區管理授權沿既有方案處理，不能只靠上傳或單項通過開權。
6. 同一文件一項通過、另一項待補時顯示各自結果。替換／補件須新版本與重新檢核受影響項目，不可靜默覆蓋已審原件；版本保留／重審操作細節待確認。

現有community_registrations的NOT NULL、欄位INSERT grants及無本人UPDATE證據不直接支持完整草稿／補件；需後續提出相容擴充與授權方案，不能只加按鈕宣稱完成。候選只附加申請文件metadata、兩類requirement引用／版本及獨立review_events；不存二進位於公開欄位，不取代原申請資料。正式狀態值與草稿儲存模型待設計審核。

## 4. 私人儲存及安全方案（先規劃，不設定）

| 面向 | 候選安全設計與驗收邊界 |
|---|---|
| 私人檔案 | 私人bucket／等效私人儲存，匿名及其他租戶不可列出／讀取；不使用public URL。隨機object key與私密metadata，不把姓名、電話、地址放路徑；原始檔名亦可能含個資，不送公開日誌 |
| 身分與存取 | owner僅存取自己申請；平台僅核准的審核職責可查必要文件，客服不因客服身分自動讀原件；新／舊社區管理員不自動繼承他人證件存取權。Auth與Storage政策／RPC皆需獨立審查，不因認得object key可讀 |
| 預覽／下載 | 每次重新驗證申請與文件權限，優先受控代理或短效限範圍signed URL；不寫入公開HTML、分析／錯誤追蹤、Referer或快取。signed URL到期前可能仍可被持有者使用，TTL／撤權策略待確認，不能宣稱撤權後既有連結立即失效 |
| 格式檢查 | 候選白名單PDF／JPEG／PNG，實際清單待確認；副檔名、宣告MIME及檔案內容／魔術碼由伺服器交叉驗證，不能只檢前端。加密／損壞／含主動內容檔案的處理、掃毒與安全預覽方案先確認；未通過不提供審核者直接執行／預覽 |
| 容量與濫用 | 伺服器限制單檔bytes、頁數／像素、每申請檔數與總容量／上傳速率；具體數值待確認，不擅定MB。前端同規格提示；串流／分段上傳也須限額；未設定核准規格前不可正式開放無上限上傳 |
| 隔離與一致性 | 檔案先私人隔離待檢查，上傳完成與安全可用狀態分開；伺服器驗所有引用的所有權／申請關係，防跨申請或跨租戶任意key引用。同檔兩引用只建兩項資格關聯，不重傳或自動複製審核決定 |
| 個資最小化 | 提示只傳必要頁面，遮蔽不必要的住戶名冊、證號、電話等，審核必須可辨資訊與可遮範圍待定。不做公開OCR索引或模型訓練輸入，不在公開社區／預約API、匯出或客服公開訊息回傳文件 |
| 稽核與保存 | 記上傳／引用／替換／查閱／審核actor、伺服器時間與版本；不可記完整文件或signed token到一般日誌。保存期限、撤件／拒絕／交接後刪除、備份副本與法定留存待確認，不能直接刪掉唯一證據 |

任何未來Storage policy、RLS、SECURITY DEFINER／RPC、服務身分或客服授權變更都須先交最小權限方案與測試，不擴大service_role表DML，也不視為A／B核准。現階段未盤點正式Storage設定，不能宣稱已私有化或有掃毒服務。

## 6. 測試規劃與實作依賴（尚未執行）

| 案例 | 預期 |
|---|---|
| 缺件草稿／送審 | 零件或只一項可存草稿且重登入可續填，正式送審由伺服器拒絕並定位缺項；直呼端點不能繞過 |
| 齊件與同檔引用 | 兩份或同份雙引用可進送審檢查；共用物件不多傳，兩項審核狀態分開；一項通過不自動通過另一項或開社區權 |
| 不同意／待補／未核准 | 不得建立正式管理權、改場地／發布／審核進駐；提交成功不等於審核通過 |
| 範例／FAQ／客服 | 每卡都有六類說明、手機／鍵盤可讀；列舉旁有等效文件提示，範例只有虛構內容；管道未配置不顯假可用入口，正式開放前檢查管道完整 |
| 租戶／申請隔離 | anon、另一申請人、他社區、新舊管理員、未獲文件授權客服不能列出／讀／引用／刪他人文件；平台審核者最小讀取並有稽核；偽造object key與申請id拒絕 |
| 格式／容量 | 偽裝副檔名／MIME、損壞、零bytes及未完整上傳、主動內容／感染、檔案過大／總量／像素超限須按定案政策拒絕或隔離；閾值正好／上下邊界以核准參數驗證，不先捏造數值 |
| 隱私／連結 | 公開API、頁面、匯出、快取、分析與錯誤日誌無原件／個資／signed token；短效連結到期拒讀，撤權與既有URL限制按實際機制驗證，測試不宣稱立即可收回已下載檔 |
| 送審併發／版本 | 送審與替換／移除同時發生不能產生缺件或錯版本送審；兩資格引用同版本，後續替換不能沿用不相符的審核決定；補件與稽核失敗不半開權 |
| 孤兒物件／重試 | 上傳成功metadata失敗、重試、同檔多引用、移除其中一項引用時保護另一項與送審證據；清理策略待保存規則核准，不刪已有案件證據 |

納入P0定稿U項、P2社區申請／私有Storage／文件版本與審核、P5隔離／上傳／隱私回歸；需先取得Storage契約與審核標準再提出權限及相容草稿設計。本輪不新增程式、SQL或實際Storage測試。前輪50–75專注人日為舊總規劃估算（營運／年度需求後最新66–100，詳營運政策設計），文件儲存／掃毒／客服依賴未定，此處不另承諾工期，P2/P5實作前依方案重估。

## 7. 年度驗證與文件版本銜接

沿[營運後台／年度重驗設計](operating-policy-revalidation-design.md)，每12個月重驗並允許管理員線上確認／更新／補件；管理員、主任委員或授權關係異動立即開啟重驗。沿用私人檔案與兩資格分別審核能力，保存每次聲明、文件版本、查驗依據及決定／操作紀錄，不複製成公開附件。

文件有效期內不代表授權仍有效，初檢齊備／未過期不得直接給正式重驗通過。年度案與管理任期／授權版本關聯，交接不自動給新者查看舊者個資；並行上傳／交接／撤權須重驗引用與actor權限，不能借重驗繞過三天交接。

正常無異常進低風險快速審核，最終正式核准機制仍待定。已確認Asia/Taipei前30／14／1天及到期當天提醒，該次正式通過後停止後續提醒；通道、發送時刻與重試仍待決。一般年度逾期停止新發布／新核准，但保留私人補件上傳、提交重驗、進度及既有活動／必要聯絡；補件成功不等於通過，正式通過才恢復年度原因限制，其他安全原因不可順帶解除。文件證據充分性、保存／刪除仍為U／O未決項。P2/P5補版本一致性、有效文件但授權異動、補件／過期分類、交接並行與私有存取測試；未實作／執行。年度與上傳功能均無正式Storage變更。

本輪追加測試規劃：逾期者仍能安全上傳／補件／提交；初檢無異常只進快速審核；文件未過期但授權已撤銷轉獨立安全程序；正式通過才解除年度限制並停止該次提醒，交接／撤權不能藉私人上傳入口取得新管理權或他人文件。通知／文件／正式決定與權限版本一致性按單一設計檢查；不實作或執行測試。原66–100估算經本次細化評估保留。
