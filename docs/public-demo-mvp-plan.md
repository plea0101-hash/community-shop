## 3. 最短上線候選：獨立純靜態展示（推薦，需另確認與部署核准）

不需要真實社區、廠商、帳號、資料庫或公開資料API。可在同一repo保留商用程式，未來另建展示來源／輸出目錄，以明列檔案白名單產生僅展示HTML/CSS/JS及審過素材的產物；目錄名稱與建置方式待實作方案確認，不把目前整個repo根目錄直接當發佈輸出。

候選使用獨立展示Vercel專案與獨立展示網址，**不連正式Supabase，不繼承正式環境變數，不變更原正式專案／網域／資料**。不需要為了展示先套任何migration或開啟會員gate；不帶config.js、正式URL／key、Auth SDK、RPC／Data API呼叫。最短版不建聯絡／候補名單表單，也不串金流、通知、analytics或第三方追蹤；若要收件／追蹤另提個資與功能範圍，不默默加入。

發佈白名單排除cancellation/、sql/、tests/、測試fixtures、docs/內部規劃、package／lock／設定／.git／.env、source map與正式config；本repo公開內容本來可透過GitHub看見，排除部署不是將歷史變機密。直接路徑不能由SPA fallback回傳原登入／測試畫面，404應是中性不存在／未開放。CSP／Referrer／MIME／HTTPS等header需於未來部署方案明確配置與驗收，無API時候選connect-src 'none'並檢驗是否有必要例外，不以CORS作授權。

若現有Vercel連接repo自動發布根目錄，必須先另獲核准採獨立專案／發佈目錄／受控分支；不可直接推應用改動期待不觸發正式部署。實作與發佈可用另審分支／產物，不要求合併main或整包發佈Draft PR #2。權限、供應商帳號、網域及auto-deploy確認尚未完成。

### 正式資料庫風險的界線與替代

- 正式ACL、精確戶數API及其他舊端點風險**仍未修復**，不因展示站不連DB而宣稱已安全；尤其公開repo已有專案識別。展示隔離只切斷新展示產物對正式服務的依賴，不隔離整個正式Supabase的網路可達性。
- 原站或任何舊部署若仍公開載入正式API，須另行盤點並提出最小保護／限制存取／下架或安全頁切換方案，任何實際處理另經核准，本輪不操作。不得從新展示站提供原站、取消原型或正式API的業務入口。
- 無正式權限時可先審核「獨立無DB展示產物」而不是跳過ACL風險。若擬在舊API未修前對外展示，必須由本人另行明確核准隔離方案、舊環境處置與殘餘風險／責任紀錄；不能由Codex接受或拿此當A／B豁免。未完成此決策，維持No-Go。
- 如要求同一正式域名、即時真社區或資料庫連線，則不是這條最短純靜態路徑：先取去識別化最新ACL/RLS／公開欄位與函式契約並獲正式變更核准，原API不得以只改顯示掩蓋資料。A只撤bookings目標TRUNCATE，不修戶數、其他表或defaults；B仍受supabase_admin角色權限阻擋，不能自行拆SQL／提權。
- 次選為獨立展示Supabase專案、只含合成公開資料且無正式資料／key／連線，需另核准建置、預算與最小ACL／RLS；不是本輪授權，也非最快或必需。不能複製正式schema／defaults再假設隔離就安全。

## 7. Go／No-Go與剩餘確認

目前 **No-Go：尚未建立或驗收展示產物，也沒有正式發佈／隔離風險核准**。文件整理不是Go證據。完整判準與逐項紀錄見[驗收清單](public-demo-acceptance-checklist.md)。

需要本人確認：優先純靜態獨立專案／新展示網址或其他路徑、五區內容與不收件、預設無名單／是否需要虛構示意、舊部署／API暴露的處置與風險責任、實作授權與之後獨立部署核准；若提供正式客服／素材／網域，需合法來源與可用性。不得以這次需求規劃代填任何人工風險接受或A／B核准。

此輪只交文件，保留原商用及安全證據，完成後暫停。
