# 展示型MVP：虛擬會員與角色互動設計

## 1. 已確認範圍與版本差異

- 展示使用**獨立Vercel專案及獨立網址**，不以原正式網站作部署來源。這已是需求，不再列為是否採用的待決項；實際專案、網址、受審來源／輸出與部署核准仍待後續處理。
- 網站名稱可能改變，名稱、Logo、title／相關文案需集中替換，不依賴固定品牌網域。不因改名更動完整商業規則或正式系統。
- 提供平台管理員、社區管理員、廠商會員、一般訪客四種身分，以醒目「模擬體驗」角色選擇切換，不需真帳密、不用正式或其他真Auth。一般訪客是無帳號的瀏覽模式，不新增住戶會員。
- 三個角色後台皆有基本模擬操作與可見狀態變化。它們是新製作的展示頁，不直接發佈原cancellation、正式管理端點、測試原始碼或config。
- 全部資料為虛構，顯示「非真實會員／非正式預約／非真實金流」。無正式Supabase、Auth、RPC、Data API、Storage或正式寫入，也不需要任何資料庫。
- 原純內容五區保留作訪客入口；原3–5日只適用舊純內容範圍，本輪最小可互動版取代為8–12日。全部仍是計畫，不等於已存在後台或安全授權。

## 2. 入口、模擬狀態與安全界線

首頁→「選擇身分，開始模擬體驗」→四張角色卡（含各角色能體驗什麼）→該角色工作區。全站固定展示提示、目前角色、切換角色、退出模擬與重設展示；操作完成訊息用「已在本機模擬核准／送出」等文字，不顯示真會員登入成功或真交易成功。

**角色選擇只切換UI，不是身分驗證或權限隔離。任何訪客都可選平台管理員、查看所有虛構資料與改本機狀態。** 不設真帳密／JWT／cookie會員session，不用隱藏管理網址或前端角色判斷宣稱具備安全授權。展示中的角色篩選是演示產品流程，不能當RLS、租戶隔離或正式核准證據。

最短實作候選：同一頁籤記憶體保存單一虛構scenario，角色切換共用狀態以展示跨角色申請與核准；重新整理、退出模擬、明確重設回到初始資料。這是工期假設／待確認體驗細節，不是額外商規。無跨瀏覽器／多人共享、無匯入匯出或持久儲存；如需sessionStorage／localStorage、跨裝置或分享狀態，另提生命週期與重估，不能沿用原站storage key或真會員紀錄。

可編輯值採預設虛構選項／示意欄位，提醒不要輸入真姓名、電話、證件或帳密；不提供真上傳、表單收件、寄信／推播或支付。日期／狀態採標記的展示時鐘或場景，不啟動排程、不憑真實時鐘自動讓案例過期。輸入若提供文字須安全顯示，無eval、任意HTML或動態執行。

## 3. 各後台最小可互動範圍

每模組為一個淺層清單／摘要＋詳情或至少一種基本互動，不代表完整CRUD、報表系統或商用驗證；以下動作為展示候選，不將尚未確認的商規定案。

| 身分／模組 | 展示資料與基本模擬互動 | 邊界 |
|---|---|---|
| 平台：社區審核 | 虛構社區申請清單，切換待審／補件／核准／拒絕樣本或模擬審核一筆 | 只改展示state，不授真管理權，不處理真文件 |
| 平台：廠商審核 | 虛構公司／代表權狀態，模擬要求補件或核准／拒絕 | 不查真統編／商工API，不冒充已做代表權查驗 |
| 平台：活動 | 虛構活動列表／詳情、按狀態篩選 | 不操作正式bookings或自動取消活動 |
| 平台：財務 | 合成場地費／平台費／週結摘要，模擬試算／標記示意收款並顯示前後狀態 | 各金額旁標非真實金流；10%最低100、免費0、逐案進位後加總、含稅不加5%沿用，不接支付／入帳／發票 |
| 平台：年度驗證 | 待補／低風險／人工複核／逾期／已通過合成案例，補件分類或切換預設結果 | 正常案最終核准機制／證據未定，只能明示「載入預設已通過場景」演示後果，不制定核准標準或假稱真授權有效 |
| 平台：營運規則 | 初始10%等政策、版本／原因／生效摘要；編輯一份示意草稿並預覽差異／切換預設版本 | 本機模擬，無安全開關／SQL，不能藉展示決定未定參數範圍、啟動排程或公告；舊合成核准案費用快照不跟著改 |
| 社區：社區資料 | 虛構名稱／區域／戶數級距佔位與管理狀態，編輯示意資料 | 不含真地址、證件或精確戶數；級距端點未定不以展示造新算法 |
| 社區：場地 | 虛構場地／設備／費用摘要，選項式修改一筆 | 不寫正式venues，不假稱真場地可租 |
| 社區：檔期 | 建立／發布一筆示意檔期，顯示未發布→模擬已發布 | 非正式招商供給，需顯示非真可預約；逾期場景限制新發布 |
| 社區：進駐核准 | 待確認示意申請核准／拒絕，回映廠商進度 | 與平台廠商資格審核分開；逾期不能模擬新核准，既有合成活動不被取消 |
| 社區：活動紀錄 | 看虛構活動與操作時間軸／狀態篩選 | 僅展示活動／紀錄，不自動認定完成或寄通知；若展示完成用已確認人工／12h情境 |
| 廠商：公司 | 虛構公司／分店與授權狀態，切換／修改示意欄位 | 不建真公司帳號／認領，主帳號與分店授權只為場景 |
| 廠商：品牌 | 虛構品牌列表，切換或修改示意品牌 | 不用真商標／商品品質認證標章 |
| 廠商：進駐申請 | 選模擬已發布檔期＋虛構品牌＋實際分店，送出本機待確認申請 | 非正式預約、無庫存承諾；不沿用正式ID／API或原取消程式 |
| 廠商：審核進度 | 查看平台資格與社區場次的分開狀態，隨跨角色操作更新 | 平台資格核准不直接等於場次核准，未核准資格場景不能假裝已合法進駐 |
| 廠商：活動 | 查看模擬已核准活動／詳情與篩選 | 非真合作／預約，不轉向付款／聯絡真社區 |
| 一般訪客 | 瀏覽五個介紹區、虛構示例／空狀態、進入角色選擇 | 無正式帳號，不收資料，不稱住戶會員 |

最小跨角色連續案例：廠商選品牌＋分店送出假申請→社區看到同一筆待確認、模擬核准／拒絕→廠商進度與雙方活動畫面一致，平台活動清單同步；拒絕不生成核准活動，重按不生成多筆。角色切換不混入真資料，重設後全套還原。

平台社區／廠商審核、年度／財務／政策各至少一個可重設淺層互動，不能只用靜態截圖滿足「可模擬操作」。跨後台的更多相依（如模擬核准後解鎖資料編輯）需先列scenario契約，不能無限擴成完整商用狀態機。正常年度核准未定維持樣本切換，通過後週期及提醒演示遵守最新日期規則；通知只顯示虛構紀錄，無外送服務。

## 4. 品牌集中替換與獨立展示來源

候選以專屬展示content／brand設定集中管理：顯示名稱、短名、Logo／圖示資產、Logo alt、網站title／description／OG、導覽／頁尾／空狀態／角色標題與提示文案。所有文字與素材引用共用該來源，fallback為中性展示標誌；實際新名稱／Logo／授權仍待本人提供或確認。不將「鄰里好店」寫死在路由、localStorage key、CSS選擇器或流程判斷，文件中的原專案名可保留。

這是**公開展示內容設定**，不是原config.js或任何含key的正式環境設定，不攜入Supabase專案識別。候選採打包時載入以避免runtime API依賴；相對URL與部署環境產生的網站origin處理分享／canonical資訊，不固定正式品牌網域。只切展示部署網址或更換品牌素材後，角色入口、資產、標題與畫面仍可用；不得改原正式域名／網站設定。

獨立Vercel專案只發布新的白名單展示產物，不以原正式網站作來源／fallback，也不整包發佈PR或測試fixture。可復用版面概念，不直接公開cancellation、原管理端點、sql／tests／內部docs／正式config。手工建立全新虛構展示資料集，只含允許公開示意欄位；不可因叫「fixture」就複製現有測試原始碼／真品牌種子。展示JS作公開產品程式可發布，測試程式不在產物內。

## 5. 安全與驗收新增重點（全部未實作／未測）

- 全頁、角色選擇、各後台、狀態訊息與財務明示模擬；所有樣本非真實會員／預約／金流。真服務申請／預約／付款仍未開放，允許的只是新本機模擬介面。
- 四角色能自由切換；不用帳密、不產生Auth/token請求，不聲稱安全授權。直接開展示路由可選角色或看假資料，不應轉到正式登入或原取消頁。
- 跨角色狀態一致、重複操作可控、退出／刷新／reset依最終採用的生命週期還原；不使用真storage或既有KEY，不在瀏覽器之間共享。
- 角色模擬、財務試算、年度與政策操作均無任何正式請求／寫入，網路僅經審展示資產；無email／SMS／webhook／支付／真上傳。外網不可用時仍可演示已載入的情境，不能fallback正式API。
- 品牌與title／meta／Logo／文案一次替換核對；不同展示origin及相對資產可用，無硬編碼正式品牌域名、Supabase網址／key；自訂文字不成為XSS／任意HTML。
- 原C01／C05／C08／C09／C12及Go／No-Go須允許新作的角色介面與記憶體模擬，繼續禁止正式登入、原型入口與真敏感資料，不能用舊「零互動」條件驗新MVP。
- 舊正式ACL／公開API風險沒有因角色模擬而修復；隔離／舊環境處置及本人風險／部署決策保留，不自填人工簽認。現在仍No-Go。
